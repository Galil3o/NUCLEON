# Nucleon v0.1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build the headless Nucleon engine that reads Proton mail (read-only), classifies it with a quarantined model, auto-applies reversible labels, and stages reply drafts for native human sending — with an opt-in metadata-only journal.

**Architecture:** A deterministic core orchestrates four seams behind interfaces — `MailStore` (mail access), `Classifier` (quarantined model), `gate` (policy), `Journal` (audit) — so the whole pipeline is tested against in-memory fakes with no live mailbox or model. Real adapters (`ImapMailStore`, `LLMClassifier`) are thin and unit-tested with stubs; their live acceptance against a real Bridge/model is a post-v0.1 gate.

**Tech Stack:** Python ≥ 3.11, `pydantic` (models/config), `PyYAML` (config), standard library for IMAP/MIME/HTTP/hashing (`imaplib`, `email`, `urllib.request`, `hashlib`). Dev: `pytest`. `src/` layout.

**Spec:** `docs/CONCEPT.md`

## Global Constraints

- Repository language: **English**. License: **Apache-2.0**.
- **No SMTP / no send path** in v0.1 (drafts-only). No `Action` type for send exists.
- **No deletion** in v0.1 (no expunge, no `\Deleted`).
- **No raw mail persisted:** anything written to disk (journal, state) holds **metadata and hashes only** — never bodies, subjects, addresses, or attachments.
- **Account-neutral:** the engine holds no account identity, credentials, or data; everything comes from config. `config.example.yaml` contains **placeholders only**.
- **Minimal dependencies:** prefer the standard library; the only runtime deps are `pydantic` and `PyYAML`.
- Draft label is exactly `nucleon/proposed`. Draft staging target is `drafts` (native Drafts) or `outbox` (`Nucleon/Outbox`), from config.
- All Sent access and reconciliation are **read-only**. Body reads use `BODY.PEEK` (flags must not change).

## Review Focus

- **Prompt injection in message content** must not change which actions the gate allows — the gate reads only validated fields, never instruction-like text. → Task 5.
- **Malformed / attacker-shaped model output** (non-JSON, missing or extra fields) is rejected, never executed. → Task 4.
- **Re-processing a message** must not create a duplicate draft (idempotency via journal / stable staging). → Task 8.
- **Body fetch uses `BODY.PEEK`** and never sets `\Seen` or other flags. → Task 9.
- **The journal never persists** bodies, subjects, or addresses — metadata and hashes only. → Task 7.

### Task 2: Core data models

**Files:**
- Create: `src/nucleon/models.py`
- Test: `tests/test_models.py`

**Interfaces:**
- Produces:
  - `MessageRef(account_hash, mailbox, uidvalidity: int, uid: int, message_id_hash: str | None, raw_hash: str)` with `@classmethod from_source(account_hash, mailbox, uidvalidity, uid, message_id: str | None, raw: bytes) -> MessageRef` (hashes via `hashlib.sha256`) and `key() -> str` (stable `"{account_hash}:{mailbox}:{uidvalidity}:{uid}"`).
  - `MessageMeta(ref: MessageRef, subject: str, from_addr: str, to_addrs: list[str], date, in_reply_to: str | None, references: list[str])` — **in-memory only, never persisted.**
  - `Classification(category: str, labels: list[str], urgency: Literal["low","normal","high"], needs_reply: bool, draft_subject: str | None, draft_body: str | None)`.
  - `Action` union: `ApplyLabel(ref, label)`, `StageDraft(ref, subject, body, in_reply_to, references, target, label)`. **No send/delete action types exist.**
  - `JournalEntry(ref_key: str, account_hash, mailbox, uid: int, message_id_hash, raw_hash, action: Literal["classified","drafted","marked_sent"], status: str, ts: datetime)` — **no body/subject/address fields.**

- Create: `src/nucleon/engine.py`

**Interfaces:**
- Consumes: `MailStore`, `Classifier`, `Journal`, `Config`, `gate.decide`, `actions.execute`.
- Produces:
  - `run_once(store, classifier, journal, cfg) -> RunReport` — for each ref in the window not already in the journal: `fetch_meta` → `fetch_body_text` → `classify` → `gate.decide` → `execute` each action → `journal.record(... "drafted"/"classified")`.

## Out of scope for v0.1 (seams left open)

SMTP/sending (the optional-send seam), deletion, a web/API frontend (the frontend seam connects to the engine later), non-Proton providers (additional `MailStore` implementations), and attachment/Drive handling. None require changes to the interfaces defined above.
